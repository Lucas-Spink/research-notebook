# Testing guide

Patterns every contributor, human or AI, follows. The rules themselves are in `AGENTS.md` section 8.

## File naming decides which suite runs

| Suffix | Suite | Command |
| --- | --- | --- |
| `*.test.ts` in `packages/`, `extensions/` | unit | `pnpm test:unit` |
| `*.test.tsx` / `*.test.ts` in `apps/desktop/src` | ui (jsdom) | `pnpm test:unit` |
| `*.a11y.test.tsx` | ui, accessibility | `pnpm test:a11y` |
| `*.property.test.ts` | property | `pnpm test:property` |
| `*.golden.test.ts` | golden | `pnpm test:golden` |
| `*.fixtures.test.ts` | fixtures | `pnpm test:fixtures` |
| Rust `#[test]` and `proptest!` | rust | `pnpm test:rust` |
| `crates/nb-fs/tests/fs_safety.rs` | filesystem safety | `pnpm test:fs-safety` |

## Determinism

Pure code receives its clock and ID generator as arguments.

```ts
export interface Env {
  now: () => Date;
  newId: () => Ulid;
}

export function createExperiment(project: ProjectModel, input: NewExperiment, env: Env): ProjectModel {
  // uses env.now() and env.newId(); never Date.now() or Math.random()
}

// In tests
const env = { now: () => new Date("2026-09-15T10:00:00Z"), newId: sequentialIds("01JAX") };
```

## Property tests (TypeScript)

Read the case count from the environment so CI can run short on pull requests and long at night. Keep arbitraries in `test/arbitraries.ts` next to the package so all property tests share them.

```ts
import fc from "fast-check";
import { describe, it, expect } from "vitest";
import { parseExperiment, serialiseExperiment } from "../src";
import { experimentDocument } from "./arbitraries";

const numRuns = Number(process.env.FC_NUM_RUNS ?? 200);

describe("experiment.md round-trip", () => {
  it("parse(serialise(doc)) equals doc", () => {
    fc.assert(
      fc.property(experimentDocument(), (doc) => {
        const text = serialiseExperiment(doc);
        const parsed = parseExperiment(text);
        expect(parsed.ok).toBe(true);
        if (parsed.ok) expect(parsed.value).toEqual(doc);
      }),
      { numRuns },
    );
  });

  it("serialise is canonical: serialise(parse(text)) equals text", () => {
    fc.assert(
      fc.property(experimentDocument(), (doc) => {
        const text = serialiseExperiment(doc);
        const again = parseExperiment(text);
        if (!again.ok) throw new Error(again.error.message);
        expect(serialiseExperiment(again.value)).toBe(text);
      }),
      { numRuns },
    );
  });
});
```

When fast-check reports a failure it prints the seed and the shrunk counterexample. Add the counterexample as an ordinary unit test named after the bug before fixing it.

## Property tests (Rust)

```rust
use proptest::prelude::*;

proptest! {
    #[test]
    fn sanitised_names_are_windows_safe(name in "\\PC{0,200}") {
        let out = nb_fs::names::sanitise(&name);
        prop_assert!(nb_fs::names::is_windows_safe(&out));
        prop_assert!(out.chars().count() <= 64);
        prop_assert_eq!(nb_fs::names::sanitise(&out), out.clone()); // idempotent
    }
}
```

`PROPTEST_CASES` controls the case count. Commit the `proptest-regressions/` files that proptest writes on failure.

## Filesystem safety

`fs_safety.rs` copies a fixture project to a temporary directory, records a snapshot (relative path, size, modification time, SHA-256) of everything outside `_notebook/`, runs every backend operation in the integration scenario, then asserts the snapshot is identical. Any new backend operation must be added to the scenario in the same pull request.

The one exception is creating a project, which appends to the root `.gitignore` and `.gitattributes` (ADR-0021). `snapshot_outside_notebook_except` leaves those two names out, and the test asserts they only gain lines. Do not add other names.

## Golden files

Golden tests compare output with committed files under `__golden__/`. Update them only with `pnpm golden:update` and describe why each changed line is correct in the pull request. Never update golden files to silence a failure you do not understand.

## Fixtures

- Copy fixtures into a temporary directory before opening them; never open the committed folder directly.
- Released fixture folders (`fixtures/projects/format-v1/...`) are immutable. Add a new fixture for a new case.
- `large` is generated by `pnpm fixtures:generate` and not committed.

## Mock servers

Zotero tests use recorded responses served from `127.0.0.1` on a random free port. Record new responses manually against a real Zotero instance, strip personal data, and commit them under `crates/nb-zotero/tests/recordings/`.

## What a good test checks

- Observable behaviour through public functions, not private implementation details.
- One behaviour per test, named as a sentence: `opens_newer_format_read_only`.
- Failure messages that say what was expected and what happened.
- Both success and failure paths, especially read-only fallbacks.
