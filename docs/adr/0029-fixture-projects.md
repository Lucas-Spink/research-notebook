# ADR-0029: Fixture projects

- Status: Proposed
- Date: 2026-01-06
- Deciders: maintainer
- Spec sections affected: 12.3; gates S2-G01, S2-G03, S2-G04, S2-G10, S2-G14

## Context

S2-T13 creates the fixture projects spec 12.3 requires: `minimal`, `typical` (3 questions, 12 experiments), `large` (500 experiments, 5,000 artefacts, generated by a committed script, not committed itself), `edge-cases` (Unicode names, CRLF files, BOM, unknown keys, passthrough Markdown, detached references, trashed sources) and `malformed` (files expected to open read-only). Two things were left open by earlier tasks, both put to the maintainer with the plan and answered "go with your recommendations":

- format-v1.md 3.2 and section 8 point 2: gate S2-G01 ("every file in every fixture" round-trips byte for byte) cannot hold for `edge-cases`, which is deliberately non-canonical, and format-v1.md says *"S2-T13 must mark which fixture files are canonical."*
- Gate S2-G10's own row names `pnpm test:fixtures -- future-format`, but spec 12.3's five required fixtures do not include a name for it, and a `format_version: 2` project must be read-only before anything else is touched (format-v1.md section 6), so it cannot share a folder with `malformed`'s per-file failures.

## Decision

1. **A `fixture.json` at the root of each fixture**, a sibling of `_notebook/`, never inside it:
   ```json
   { "kind": "edge-cases", "canonical": false }
   ```
   `minimal`, `typical` and `large` are `canonical: true`; `edge-cases` is `false`; `malformed` and `future-format` are also `false` (canonicity does not apply — they do not parse). The fixtures-compatibility suite (`fixtures/support.ts`) reads this file directly with `JSON.parse`; `packages/format` never sees it, so rule 2 (one parser) is untouched. It decides which check a fixture gets: `fixtures/canonical.fixtures.test.ts` asserts `serialise(parse(file))` equals `file` only where `canonical` is true.
2. **`future-format` is a sixth, small fixture folder**, holding only `_notebook/project.yaml` with `format_version: 2`. Nothing else is ever read once the version probe sees it (format-v1.md section 6), so nothing else is needed. Spec 12.3 lists five fixtures as *required*, not exclusive.
3. **`minimal`, `typical` and `large` are generated, not hand-typed**, by `scripts/lib/build-notebook.mjs` using `packages/format`'s own operations (`newProject`, `createQuestion`, `createExperiment`, `editExperiment`, `editExperimentSection`) with a deterministic clock and ULID source, so every file is canonical by construction and two runs produce identical bytes. `scripts/generate-large-fixture.mjs` (committed, per the task's agent notes) calls it with 20 questions × 25 experiments = 500, and 10 fabricated link-mode artefacts per experiment = 5,000; its output is not committed (already ignored by the pre-existing `fixtures/projects/*/large/` rule in `.gitignore`). `minimal` and `typical` were generated once, by hand, from an uncommitted driver script in this session, and their output is committed as static files — there is no legitimate later use for regenerating them (fixture folders are immutable once merged, AGENTS.md section 6), so no such script is kept in the repository.
4. **Large's artefacts are fabricated link-mode records**, not real captured files: schema-valid hashes and paths that name nothing on disk. Nothing in the application reads `artefacts.yaml` yet (ADR-0027 point 5: the table shows "None yet" for Results), so real evidence bytes would cost disk space and generation time for no test coverage this stage exercises.
5. **`edge-cases` and `malformed` are hand-written**, since their whole point is to be exactly what a generator would never produce: CRLF, a byte-order mark, a duplicated YAML key, a missing frontmatter fence. Each byte-level property (the BOM, the CRLF) is verified directly against the raw file bytes, not inferred.
6. **`malformed`'s failures are representative, not exhaustive**: one file for each of the four `FormatError` kinds a single-file parse can produce — `frontmatter` (no closing fence), `schema` (a disallowed `status`), `syntax` (a duplicated key), `body` (a repeated `## Methods`) — plus one ordinary valid question, to show a malformed file makes only itself read-only (format-v1.md section 6, spec P6), not the whole project. Two files sharing one `id` (spec P6's other malformed case) is **not** included here: it can only be found by the project loader (`packages/format/src/notebook/arrangeNotebook`), which already has its own inline tests for exactly this (`packages/format/src/notebook/arrange.test.ts`, from S2-T10) — a fixture is not needed to cover it again.
7. **The fixtures-compatibility suite stays inside `packages/format`'s public API.** It proves what a fixture's files parse to and what they refuse to become, using `parseProject`, `parseQuestion`, `parseExperiment`, `parseArtefacts` and their serialisers. It does not import the webview's project-mode logic (`apps/desktop/src/features/projects/model`): that translation from a `FormatError` to a read-only banner is already tested there (S2-T06's `mode.test.ts`). "Editing attempts" and "closing" (the rest of S2-G04's pass criterion) are covered by the fact that a file which fails to parse is never loaded into a `NotebookState`, so no `Plan` a write command would carry out can ever name it — nothing to drive by hand here.
8. **`fixtures/` is not a pnpm workspace package** (it matches none of `pnpm-workspace.yaml`'s globs), so its test files import `packages/format` by relative path (`../packages/format/src`), not by package name. A new `fixtures/support.ts` holds the shared harness: copying a fixture to a fresh temporary directory before it is opened (docs/testing-guide.md), reading its `fixture.json`, and reading raw bytes or text.
9. **`fixtures/projects/**` is added to `.prettierignore`.** Prettier does not know format-v1.md's flow-object rule (no space inside `{}`) and reformatted several generated and hand-written fixture files as a normal edit in this task would otherwise do again; it is excluded the same way `packages/format/src/__golden__/` already is, for the same reason (canonical output compared byte for byte).
10. **`scripts/lib/build-notebook.mjs` is plain JavaScript with a `.mjs` extension**, not `.ts`: it holds no TypeScript-specific syntax, and a `.ts` file that dynamically imports `packages/format` (there is no other way to reach a TypeScript source file's real types from a plain script) is typed `any` throughout by the nature of a dynamic `import()`, which under this repository's strict ESLint configuration became eighty `no-unsafe-*` errors with no corresponding safety gained. `.mjs` is not covered by the typed-linting file glob, matching the two existing scripts (`scripts/export-format-schemas.mjs`, and this task's own `scripts/generate-large-fixture.mjs`) that already use the same "Node runs TypeScript sources directly" trick to reach `packages/format`.

## Not in this task

- The `open-large` benchmark (S2-G14) itself: no `*.bench.*` harness exists anywhere in this repository yet, and building one means driving the real Tauri window (spec 12.1's Performance tooling row). This task supplies the fixture it will use.
- Cross-platform handoff (S2-G15): a nightly CI job, not a fixture.
- Offering to renumber a duplicate ref, or any other application behaviour: this task adds test data and two small scripts, nothing else.

## Alternatives considered

| Option | Why not chosen |
| --- | --- |
| A single project-wide canonical registry file instead of one `fixture.json` per fixture | A fixture is meant to be self-contained; a registry elsewhere could drift from the folder it describes without either side noticing. |
| Fold `future-format` into `malformed/` as a subfolder | `fixtures/harness.fixtures.test.ts` and `fixtures/support.ts` both assume one level of nesting (`format-v1/<name>/`); a deeper nesting would need its own harness rule for one fixture. |
| Make `fixtures/` a real pnpm workspace package, importing `@research-notebook/format` by name | Adds a `package.json` and a workspace-glob change for a directory that is deliberately test data, not a package; the relative import is one line and matches the resolution `scripts/` already uses. |
| Commit real captured evidence files for `large`'s artefacts | Nothing reads them yet (ADR-0027); the disk and generation cost buys no test coverage this stage exercises. |
| Keep a permanent `scripts/generate-committed-fixtures.mjs` for `minimal`/`typical` | Fixture folders are immutable once merged; there is no legitimate future call to re-run it, unlike `generate-large-fixture.mjs`, which is used on demand for the benchmark. |
| A `scripts/tsconfig.json` so `build-notebook.ts` type-checks as TypeScript | The file has no TypeScript-specific syntax and its one dynamic import makes everything `any` regardless; `.mjs` matches its two sibling scripts and needs no new tsconfig. |

## Consequences

- **`edge-cases` needs no maintainer approval to gain a new case later**: a new hand-written case is added to the same folder only *before* this fixture is merged; once merged, it is immutable like every other fixture, and a new characteristic gets a new fixture folder (docs/testing-guide.md).
- **A fixture without `fixture.json` fails loudly.** `openFixture` throws if it is missing, rather than guessing a default, so a future fixture folder is never silently skipped by S2-G01.
- **The two hygiene decisions above (canonical marker, future-format's own folder) are this ADR's whole content**; nothing here changes `packages/format`, `nb-fs`, or any shipped application behaviour.
- **Windows only.** Every fixture and the generator were made and verified on Windows; the byte-order-mark and CRLF bytes were checked directly, but nothing here has been opened on macOS.
- **Tests.** `fixtures/harness.fixtures.test.ts` (updated wording only), `fixtures/canonical.fixtures.test.ts` (S2-G01, and `large`'s exact counts when generated), `fixtures/edge-cases.fixtures.test.ts` (S2-G03 against the real fixture, complementing the existing inline cases in `packages/format/src/preserve-unknown.test.ts`), `fixtures/malformed.fixtures.test.ts` (S2-G04, S2-G10).
